# Landau and Lifshitz Mechanics: Solution Manual

Worked solutions to the problems of *Mechanics* by L. D. Landau and
E. M. Lifshitz (Course of Theoretical Physics, Volume 1, third edition),
written in LaTeX by **Pierre-Olivier Bolduc**. The solutions follow the book
chapter by chapter and section by section, with the book's numbering.

This is an unofficial, ongoing solution manual and a personal learning
project: I am an engineer, not a physicist. Corrections and suggestions are
welcome: feel free to open an issue or a pull request.

- **[Website](https://pobol2.github.io/Mechanics-Landau-Solution/)**: every
  problem by chapter and section, with a page and a PDF for each solved
  problem
- **[Full manual (main.pdf)](main.pdf)**: all the solutions in one PDF
- **[Progress](#progress)**: which problems are solved so far
- **[Numerical studies](#numerical-studies)**: independent checks and how to run them

## Organization

The manual follows the book: L. D. Landau and E. M. Lifshitz, *Mechanics*,
third edition (1976), Course of Theoretical Physics, Volume 1,
Butterworth-Heinemann, ISBN 978-0-7506-2896-9. Its seven chapters are divided into the book's
sections that have problems, shown with the book's numbers (§5, §7, ...), and
the problems are numbered within their section as in the book: §9 Problem 3
is the third problem of §9. Sections without problems are left out. Every
problem of the book is included, with its parts; the problems not solved yet
have their question only and are marked "Not done".

## How it is built

The manual uses the
[Solution Manual Template](https://github.com/pobol2/Solution-Manual-Template),
included as a Git submodule in `template/`. Its `template/solution-manual/`
folder provides the shared framework: the document classes (problem, solution
and answer boxes, title page, headers), the general figure class and the
`latexmk` build rules. The template's own sources are never edited here.

Everything specific to Mechanics stays in this repository:

```
main.tex              Titles, author, numbering, completion tracking, chapters
Chapters/             One file per chapter of the book, divided into sections
Figures/*.tex         Standalone TikZ figures (compiled with LuaLaTeX)
mypackages.sty        Packages of the manual
mycommands.sty        Commands of the manual
myfigures.sty         Physics figure styles: bodies, vectors, 3D views, fields
SolutionFigure.lua    Numerical field lines and equipotentials for the figures
latexmkrc             Loads template/solution-manual/latexmkrc; writes the
                      completion report into this README
site/                 Website: builder, style and problem titles
Simulations/          Numerical checks of solutions (see Numerical studies);
                      run separately, the manual includes their saved figures
physics-engine/       Submodule: the particle-mechanics library they use
.github/workflows/    Website deployment to GitHub Pages (see Website)
```

The physics-specific figure styles and the Lua field tools are deliberately
kept local in `myfigures.sty` and `SolutionFigure.lua`: the template stays
general, and the shared figure class loads `myfigures.sty` automatically.

## Writing a solution

Each section of a chapter file starts with the book's number and title:

```tex
\textbooknumber{\S 21}
\section{Free oscillations in one dimension}
```

and each problem has three arguments, the question, the solution and the
final answer. An unsolved problem has an empty solution and answer:

```tex
\begin{problem}
{
Express the amplitude and initial phase of the oscillations ...
}
{}
{}
\end{problem}
```

To solve it, write the solution in the second argument and the boxed answer
in the third. A problem in parts gives its main question with `{}{}` and is
followed by one `subproblem` per part, with the same three arguments. Then
rebuild with `latexmk`.

Completion is tracked automatically: a problem or part is done when its
solution is not empty, and a problem in parts when all its parts are done.
Unfinished problems show "Not done" in their title and in the contents; the
[Progress](#progress) section of this README lists them by chapter and
section. Both are refreshed by every build, so there is no list to maintain; the commit hook (see
[Committing](#committing)) commits `README.md` with `main.pdf`.
To mark a problem whose solution is only partial, add `[not done]`
(`\begin{problem}[not done]`); `[done]` marks a part complete without a
solution, e.g. one answered only.

References:

- another problem: `\probref{\S 9}{1}` gives "§9 Prob. 1" with a link,
  also in the problem statements ("The same as \probref{\S 18}{4}"); a part
  is added after it, `\probref{\S 5}{3}(c)`;
- equations: the usual `\label` and `\eqref`, with labels named after the
  section and problem, `S9P1_M` for §9 Prob. 1;
- the book's own figures and equations, "(Fig. 22)", "(44.10)", are plain
  text. When the manual has its own drawing of the system, link to the
  problem that shows it: `(see the figure in \probref{\S 5}{2})`.

A figure is a standalone file `Figures/<name>.tex`, included with
`\includegraphics{Figures/<name>.pdf}`; the build compiles it. Figures are
named after their section and problem like the labels, with the part if any:
`S5P1` for §5 Prob. 1, `S9P3a` for §9 Prob. 3(a).

## Getting the sources

Clone with the submodule:

```sh
git clone --recurse-submodules https://github.com/pobol2/Mechanics-Landau-Solution.git
```

In an existing clone, or if `template/` is empty:

```sh
git submodule update --init --recursive
```

Then enable the commit hook (once per clone, see [Committing](#committing)):

```sh
git config core.hooksPath .githooks
```

## Building

Prerequisites: a TeX distribution (MiKTeX or TeX Live) with pdfLaTeX,
LuaLaTeX and `latexmk`, and Perl (on Windows, e.g. Strawberry Perl). Allow
MiKTeX to install missing packages when prompted.

From the repository root, run:

```sh
latexmk
```

pdfLaTeX compiles the manual, and LuaLaTeX compiles each figure only when its
source, `myfigures.sty`, `SolutionFigure.lua` or a shared class changes.

| Location      | Contents                                                  |
| ------------- | --------------------------------------------------------- |
| `main.pdf`    | The finished manual (kept in Git)                         |
| `README.md`   | Its Progress section is rewritten when completion changes |
| `Figures/*.pdf` | Generated figures (ignored by Git)                      |
| `build/`      | Temporary files: logs, SyncTeX, figure compilations (`build/figures-aux/`) |

### Committing

The hook `.githooks/pre-commit` runs `latexmk` before each commit (from the
terminal or VS Code) and adds `main.pdf` and `README.md` to it, so the
committed PDF always matches the committed sources; a failed build stops the
commit. The PDF has no build date or random ID (see `main.tex`), so it only
changes when its content does. `git commit --no-verify` skips the hook.

### VS Code

Install the LaTeX Workshop extension and open the repository folder. The
tracked `.vscode/settings.json` makes **LaTeX Workshop: Build LaTeX project**
(or saving a file) run the same `latexmk` command. The viewer shows
`build/main.pdf`, with SyncTeX forward and inverse search.

## Numerical studies

Selected solutions include numerical checks using the
[`physics-engine`](physics-engine) particle-mechanics library. The engine
integrates Newton's equations independently of the manual's analytical results.

| Solutions | Checks |
| --- | --- |
| §5 Problems 1–4 (including 3(a–c)) | Cartesian particle motion against equations derived from the Lagrangian |
| §7 Problem 1 | Transmission angles and reflection at a smooth potential step, excluding the exact threshold |
| §10 Problems 1–2 | Time scaling for masses m and 4m, and potentials U and 4U, in an anharmonic well |

The studies report quantitative errors and check numerical convergence;
verification fails if the required agreement or convergence is missing.
These are checks of selected cases, not general proofs. Saved CSV data and
PGFPlots sources let `latexmk` build the manual without rerunning simulations.

To run a study, install CMake 3.20+, a C++17 compiler and Python 3.11+, then
run from the repository root:

```sh
git submodule update --init physics-engine
cmake -S Simulations -B build/simulations -DCMAKE_BUILD_TYPE=Release
cmake --build build/simulations --config Release
python -m venv build/simulations-venv
build/simulations-venv/Scripts/python -m pip install -r Simulations/requirements.txt
build/simulations-venv/Scripts/python Simulations/study.py S7P1
latexmk
```

Replace `S7P1` with another study ID, such as `S10P1` or
`S10P2`. On Linux and macOS, use `bin/` instead of `Scripts/`; with MinGW,
add `-G Ninja` to the configure command. Eigen is downloaded if needed.
See [the simulation notes](Simulations/README.md) for parameters, error
bounds, regression commands and how to add a study.

## Website

The [website](https://pobol2.github.io/Mechanics-Landau-Solution/) has a
catalogue page: the progress, a link to download the full manual, and every
problem of the book by chapter and section. Each solved problem opens its own
page, which shows its PDF (cut from `main.pdf`) with links to open or download
it, its parts and the previous and next solved problems. Unsolved problems have no
page: they are greyed out, marked *Not done* and open their PDF, which has the
statement only. In a problem PDF, links to another problem open that problem's
PDF, at the right page.

Each problem has a stable ID from the book's numbering: `s9-p3` is §9
Problem 3, its page is `problems/s9-p3.html`, its PDF `pdf/s9-p3.pdf`, and
`#s9-p3` is its line in the catalogue. The pages carry a title, description,
canonical URL and structured data (schema.org) of their own, built from the
section titles and `site/problems.toml`; they never reproduce the book's
problem statements.

`site/build.py` builds the site from committed files only (no LaTeX, no
`build/`, no `template/`):

- `main.pdf`: chapters, sections and problems (its bookmarks), the pages of
  each problem, their parts and the links between problems;
- the [Progress](#progress) section of this README: which problems are done;
- `site/problems.toml`: a short descriptive title for each problem.

The build stops if they disagree (counts, sections, unknown IDs in
`problems.toml`), if a problem PDF does not check out (pages, running
headers, links, bookmarks) or if a page does not (its canonical URL, a title
and description shared with another page, a link to a missing file, anchor or
PDF page, the sitemap). The output goes to `_site/` (ignored by Git):
`index.html`, `problems/<id>.html`, `style.css`, `main.pdf`, `pdf/<id>.pdf`,
`catalogue.json` (the catalogue as data) and `sitemap.xml` (the homepage, the
pages of the solved problems, the full manual and their PDFs).

**Setup (once):** Python 3.11 or later, then

```sh
python -m pip install -r site/requirements.txt
```

and on GitHub, **Settings > Pages > Build and deployment > Source: GitHub
Actions**.

**Preview locally:**

```sh
python site/build.py --base-url http://localhost:8000/
python -m http.server 8000 -d _site
```

then open <http://localhost:8000/> (Ctrl+C stops the server). `--base-url`
makes the links between problem PDFs point to the preview.

**Deployment:** the workflow `.github/workflows/website.yml` runs the same
build on each push to `master` and publishes `_site/` to GitHub Pages. It
never compiles LaTeX: it uses the committed `main.pdf`, which the commit hook
rebuilds. Pull requests are built and checked, but not deployed.

**Google Search Console:** the page carries the site's verification tag
(`GOOGLE_SITE_VERIFICATION` in `site/build.py`). After the first deployment,
add the URL-prefix property `https://pobol2.github.io/Mechanics-Landau-Solution/`,
verify it with the *HTML tag* method, then submit the sitemap
`https://pobol2.github.io/Mechanics-Landau-Solution/sitemap.xml` under
**Sitemaps**. (A project site cannot have its own `robots.txt`, which would
have to be at the root of `pobol2.github.io`, so the sitemap is submitted
there instead.)

**When you solve a problem**, nothing else is needed: `latexmk` (or the commit
hook) updates `main.pdf` and the progress, and the next push updates the
site, including its new page and the sitemap. Adjust its title in
`site/problems.toml` if needed: it is also the title of the page in search
results.

## Updating the template

The submodule is pinned to a specific template commit, so template changes
are adopted deliberately:

```sh
git submodule update --remote template
latexmk
```

Review the rebuilt manual, then commit the new `template` reference together
with any needed project changes. Never edit files inside `template/`; put
customizations in this repository's own files instead.
